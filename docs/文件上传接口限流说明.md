# 文件上传接口限流说明

## 1. 限流对象

限流只作用于获取预签名 URL 的接口：

```http
POST /v1/upload/presign
```

服务端先通过 `Authorization: Bearer <NewAPI Key>` 完成鉴权，再使用 API Key 对应的令牌 ID作为限流键。限流不使用客户端 IP，因此多个用户共用同一个代理出口时不会共享额度。

## 2. 默认策略

默认配置为：

```text
每个 API Key：60 秒最多 100 次
```

一次批量上传 15 个素材通常需要申请 15 个 URL，低于默认限制。实际文件上传到 TOS 的 `PUT` 请求不会经过 NewAPI，也不会消耗预签名接口额度。

## 3. 环境变量

```env
UPLOAD_RATE_LIMIT_ENABLE=true
UPLOAD_RATE_LIMIT=100
UPLOAD_RATE_LIMIT_DURATION=60
```

| 变量 | 说明 |
| --- | --- |
| `UPLOAD_RATE_LIMIT_ENABLE` | `true` 启用，`false` 关闭 |
| `UPLOAD_RATE_LIMIT` | 一个 API Key 在限流周期内允许申请的 URL 数量 |
| `UPLOAD_RATE_LIMIT_DURATION` | 限流周期，单位为秒 |

例如提高到每个 API Key 每分钟 300 次：

```env
UPLOAD_RATE_LIMIT=300
UPLOAD_RATE_LIMIT_DURATION=60
```

关闭限流：

```env
UPLOAD_RATE_LIMIT_ENABLE=false
```

Docker Compose 部署修改环境变量后，需要重新创建服务：

```bash
docker compose up -d --build new-api
```

## 4. 429 处理

超过限流阈值时，接口返回：

```http
HTTP/1.1 429 Too Many Requests
```

客户端应等待当前限流周期结束后再重新申请 URL。不要对 429 进行无间隔重试，否则会持续触发限制。

建议采用指数退避，例如等待 1 秒、2 秒、4 秒后重试，并为一次批量任务复用已成功获取的预签名 URL。

## 5. 排查清单

如果明显没有超过配置阈值仍然收到 429，请检查：

1. 请求是否实际使用了同一个 API Key。
2. 客户端是否在上传失败时反复重新申请 URL。
3. 是否存在其他调用方共用该 API Key。
4. OpenResty 是否配置了独立的 `limit_req` 限流规则。
5. 修改配置后是否重新创建了 NewAPI 容器。
